📚 Architectural Reference & Theory of Operation

Core principles of HMAC API integrity, anti-replay nonces, and side-channel mitigation

1. Canonicalization

HTTP headers and query strings are non-deterministic by default. To compute a verifiable signature, both client and server strictly sort query parameters alphabetically, normalize paths, and bind the HTTP Method and SHA-256 body hash into a deterministic newline-delimited canonical string before computing the HMAC.

2. Anti-Replay Nonce Cache

A nonce (number used once) is a cryptographically random 128-bit hex token generated for each request. The server records consumed nonces in an in-memory cache with a Time-To-Live (TTL). If an attacker captures and replays an authentic message, the duplicate nonce is identified and rejected immediately.

3. Freshness Tolerance Window

Servers cannot store nonces indefinitely without memory exhaustion. The Timestamp Tolerance Window (e.g. ±60 seconds) strictly bounds how long a request is valid. Nonces older than the tolerance window expire safely from memory because stale timestamps are rejected before the nonce cache is consulted.

4. Constant-Time Comparison

Standard string equality operators (===) terminate execution immediately on the first mismatched byte. Attackers measuring sub-microsecond response variations can deduce signatures character by character. constantTimeEqual() iterates through all characters uniformly using bitwise XOR accumulation, neutralizing timing attacks.

⏱️ Timing Attack & Side-Channel Mitigation Explorer

Why naive string comparisons leak cryptographic signatures

In a naive comparison (stringA === stringB), the CPU aborts evaluation at the first mismatched character. An adversary sending candidate signatures can observe miniscule differences in execution duration to determine how many consecutive characters matched.
